# Stationary Estimator Specification — IMU + Wheel Encoders

Constant-gain, decoupled estimator for the planar differential-drive robot
(`kalman.h` / `kalman.cpp`). The filter runs at 1 kHz. All quantities are SI:
metres, seconds, radians. Reusable incremental controllers (`pid.h`) provide
heading/yaw-rate feedback around the estimator and inner wheel-speed PI
control.

The older covariance-propagating filter and `week08/DARE.m` are deprecated.
They remain in git history and in `src/references/main.py` as historical
references, but they are not the firmware baseline. The magnetometer is not
fused; see Section 7.

---

## 1. State Vector

The filter state contains only rates and one bias:

```text
x = [ v, omega, b_a ]
```

| Symbol | Meaning | Unit |
|--------|---------|------|
| `v` | forward velocity | m/s |
| `omega` | yaw rate | rad/s |
| `b_a` | residual accelerometer bias (after startup average) | m/s² |

Position `s`, `x`, `y`, and heading `theta` are deliberately **not** states.
The firmware dead-reckons them from `v` and `omega` after every predict,
outside the filter. With no integrated state and no covariance propagation,
the filter is time-invariant: every update is a fixed linear correction and
the gains are constant.

The gyro bias `b_g` is not a state. The MPU-9250 gyro offset is removed by the
driver's startup calibration. Encoder-only wheel-omega noise is too large for
the DARE to identify a separate `b_g` state, so keeping it would add an
effectively unobservable mode.

---

## 2. Prediction (1 kHz)

```text
v += (a_raw - b_a) * dt
```

`a_raw` is the forward accelerometer reading in m/s². The firmware subtracts a
2 s stationary startup average before passing it in, so `b_a` tracks the
residual offset. `dt` is the measured tick interval and is rejected outside
`(0, 20] ms`. `omega` is not propagated by the model; it is corrected by the
gyro and wheel-yaw-rate measurements below.

---

## 3. Updates

Each measurement is a scalar correction `x += K * (z - H*x)`.

| Update | Rate | `H` row | Gain | State block |
|--------|------|---------|------|-------------|
| Wheel `v` | 100 Hz (10 ms window) | `[1, 0, 0]` | `K_WHEEL_V[2]` | `[v, b_a]` |
| Gyro `omega` | 1 kHz | `[0, 1, 0]` | `K_GYRO` | `omega` |
| Wheel `omega` | 100 Hz (10 ms window) | `[0, 1, 0]` | `K_WHEEL_OMEGA` | `omega` |

Current gain bank in `kalman.h`, generated by
`kalman_filter_tuning/solve_dare.m`:

```cpp
K_WHEEL_V     = { 0.197604345f, -0.018533077f }
K_GYRO        = 0.209729549f
K_WHEEL_OMEGA = 0.012222362f
```

The wheel `v` and wheel `omega` measurements both come from the same encoder
counts, so their noise is correlated. They are applied as two scalar updates
for code size; the fixed gains absorb the small over-trust this creates.

The wheel measurement is the quadrature encoder fallback on the current
hardware. The AS5X47 absolute-angle path remains available as an optional
upgrade; re-solve the DARE before relying on it.

## 4. Gain Stability at the Real Update Schedule

The gains are derived from block DAREs at the rates the firmware uses:
1 kHz predict and gyro, 100 Hz wheel v/omega. `tests/kalman_host/verify_gains.py`
builds the exact 100-step error transition for that schedule and also checks a
NumPy replica of the DARE against the header values.

The unit eigenvalues of the old design came from integrated `theta` and the
unobservable `b_g`; neither state exists now. The remaining modes are the
translational pair and the yaw-rate mode. When the DARE is regenerated,
replace the gain bank in `kalman.h`; do not apply a 1 ms gain at 100 Hz.

---

## 5. External Dead Reckoning

After each predict and update, `estimatorUpdate()` integrates:

```text
ds     = 0.5 * (v_prev + v) * dt
dtheta = 0.5 * (omega_prev + omega) * dt
mid    = wrapAngle(theta + 0.5 * dtheta)
x     += ds * cos(mid)
y     += ds * sin(mid)
s     += ds
theta  = wrapAngle(theta + dtheta)
poseHeading = wrapAngle(theta - theta_at_start)
```

`start()` captures `theta_at_start`, resets `s = x = y = 0`, and seeds
`v_prev` / `omega_prev`. The filter's `v`, `omega`, and `b_a` are reset; the
dead-reckoned heading is retained so the run origin is the current heading.

The log records the acceleration input and the filter velocity/yaw rate, so
distance can also be reconstructed offline with the trapezoidal rule. No
integrated quantity enters the DARE.

## 6. Outer Control Loops

`src/src/basebot_6.ino` runs the current control path every 1 ms:

```text
vCmd              = velLimiter(vRef)
headingCorrection = headingPid(wrap(headingRef - poseHeading))
omegaRefLimited   = turnLimiter(omegaRef + headingCorrection)
omegaCmd          = omegaRefLimited
                    + yawRatePid(omegaRefLimited - estimator.omega)
left,right        = polar2Cartesian(vCmd, omegaCmd) * (gear / wheelRadius)
```

With `useKfFeedback = true`, heading feedback comes from the dead-reckoned
`poseHeading` and yaw feedback from `estimator.omega`. Setting it to `false`
makes those feedback errors zero, leaving reference-limited feed-forward plus
the inner encoder wheel-speed PIs. Estimation and logging continue in both
modes. There is no outer forward-velocity PID in this control architecture.

## 7. Magnetometer and Calibration Captures

The AK8963 magnetometer is broken/unresponsive on the current hardware (zero
valid headings in both 14 Nov `cal upside` captures). It is **not fused**:
there is no mag state, no mag gain, and no `updateMag()` in the estimator.

The driver still probes the AK8963 and logs raw mag values/status for
diagnostics. `cal mag` and `cal retrymag` remain useful for checking wiring if
the sensor is repaired. Raw mag columns in the standard and calibration logs
are diagnostic only.

The calibration capture preserves the old column positions:

- columns 28-30 are estimator `v`, `omega`, and dead-reckoned `theta`;
- columns 31-32 are `b_a` and a reserved zero (former `b_g`);
- columns 33-36 are innovations (gyro, wheel v, wheel omega, reserved);
- columns 37-40 are the static innovation variances (all zero).

The reserved slots keep the serial-log layout stable without pretending the
magnetometer or gyro bias is being estimated.

## 9. Implementation Notes

- **Finite guards.** `predict` and every update reject non-finite inputs and
  leave the state unchanged. `healthy` goes false if any state becomes
  non-finite.
- **Angle handling.** `wrapAngle()` remains for the external dead reckoning;
  the filter itself has no angle state.
- **Update order.** `predict` → `updateGyro` → `updateWheelV` →
  `updateWheelOmega`, matching the firmware tick.
- **Wheel geometry.** `gear = 9.6`, `wheelRadius = 0.0315 m`,
  `wheelBase = 0.14 m` are mirrored between `basebot_6.ino` and the encoder
  conversion; keep them in sync.
- **Deprecated DARE.** `week08/DARE.m` and `week08/static_kf.mat` describe the
  old 4-state covariance filter. They are marked deprecated and are not the
  source of the current gains.

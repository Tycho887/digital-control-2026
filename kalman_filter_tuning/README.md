# Kalman Filter Tuning

Steady-state gain bank for the planar differential-drive robot, solved from the
discrete algebraic Riccati equation (DARE) in MATLAB.

The magnetometer is not part of this model. It is broken/unresponsive in the
current hardware and is treated as a diagnostic sensor only.

## Files

| File | Purpose |
| --- | --- |
| `solve_dare.m` | Main script: block DARE, gain report, multi-rate check. |
| `dare_results.mat` | Generated by the script: matrices, gains, covariances. |
| `dare_gains.csv` | Generated by the script: gain table. |
| `dare_gains.h` | Generated by the script: header-ready gain block. |
| `README.md` | This file. |

Run from this directory:

```matlab
cd kalman_filter_tuning
solve_dare
```

MATLAB R2016b or newer (local functions in scripts) and the Control System
Toolbox (`dare`) are required.

## State Vector

The filter estimates rates and one bias:

```text
x = [ v ; omega ; b_a ]
```

| Symbol | Meaning | Unit |
| --- | --- | --- |
| `v` | forward velocity | m/s |
| `omega` | yaw rate | rad/s |
| `b_a` | residual accelerometer bias | m/s² |

**Integrated quantities are not states.** Total distance `s`, heading `theta`,
and pose `x`, `y` are obtained outside the filter by trapezoidal integration:

```matlab
theta = theta + 0.5*(omega_prev + omega)*Ts;      % trapezoidal yaw rate
s     = s     + 0.5*(v_prev + v)*Ts;              % trapezoidal velocity
x     = x     + s_delta*cos(theta_mid);
y     = y     + s_delta*sin(theta_mid);
```

Equivalently, distance can be advanced with the bias-corrected acceleration:

```matlab
s = s + v_prev*Ts + 0.5*(a - b_a)*Ts^2;
```

The gyro bias `b_g` is deliberately **not** a state. The encoder-derived wheel
omega is too noisy for this DARE to identify it (the gain is effectively zero),
and the MPU-9250 gyro offset is already removed by the driver's startup
calibration. The magnetometer is not a state or a measurement.

## Block Model

The DARE is solved per observable block at the rate each measurement is
actually applied.

### Translation `[v, b_a]`

```text
v_{k+1} = v_k + Ts*(a_k - b_a,k)
b_a,k+1 = b_a,k
```

The wheel-v update runs every 10 ms, so the 1 kHz model is lifted by 10 steps:

```matlab
F_t = [1, -Ts; 0, 1];
B_t = [Ts; 0];
Q_t = B_t*(sigma_accel^2 + q_v^2)*B_t' + diag([0, q_ba^2*Ts]);
F_tw = F_t^10;
Q_tw = sum_{k=0..9} F_t^k * Q_t * (F_t^k)';
```

The `q_v` term is an unmodelled velocity disturbance, not sensor noise. It
sets how quickly the wheel correction reacts to real disturbances such as
wheel slip and bumps.

### Rotation `omega`

The gyro update runs at 1 kHz:

```text
omega_{k+1} = omega_k
Q_g = (q_om*Ts)^2
H_g = 1
R_g = sigma_gyro^2
```

The wheel-omega update runs at 100 Hz:

```text
Q_w = 10*(q_om*Ts)^2
H_w = 1
R_w = sigma_wheel_omega^2
```

`q_om` is the unmodelled angular acceleration; it is set to the 0.7 rad/s²
turn-limiter value, not to a sensor noise figure.

DARE and gain:

```matlab
[P, ~, ~] = dare(F', H', Q, R);
K = P*H'/(H*P*H' + R);
```

The resulting gain bank is:

```text
K_WHEEL_V     = [K_v, K_ba]   over [v, b_a]
K_GYRO        = K_omega       over omega
K_WHEEL_OMEGA = K_omega       over omega
```

Map it by state name into `src/src/kalman.h`:

```cpp
constexpr float K_WHEEL_V[2] = { 0.197604345f, -0.018533077f };
constexpr float K_GYRO = 0.209729549f;
constexpr float K_WHEEL_OMEGA = 0.012222362f;
```

## Noise Inputs

Defaults are from the 14 Nov `cal upside` captures
(`src/logs/device-monitor-261114-144037.log`, the 15:29 capture, and the
post-refactor 15:59 capture):

| Input | Default | Source |
| --- | --- | --- |
| `sigma_gyro` | 0.17 deg/s | 0.096-0.166 deg/s in phases 11/12; 0.08-0.34 at rest |
| `sigma_accel` | 0.12 m/s² | 0.053-0.123 m/s² in motion; 0.031 at rest |
| `sigma_wheel_v` | 0.0145 m/s | 10 ms encoder difference, forward phase |
| `sigma_wheel_omega` | 0.18 rad/s | 10 ms encoder difference, forward/turn phases |
| `q_ba` | 3e-3 m/s²/√s | placeholder until an Allan capture exists (~10 s bias trim) |
| `q_v` | 1.0 m/s² | velocity disturbance, design value |
| `q_om` | 0.7 rad/s² | turn-limiter acceleration, design value |

`q_ba` requires Allan-variance data. Run a 10-minute stationary `cal stream`
and analyze it with `src/scripts/analyze_stream.py`; use the white-noise
density and ADEV floor to replace the placeholder.

The 15:59 capture was recorded after the new gain bank was flashed. Forward
`KF/wheel v` is 1.004 with 28 mm/s RMS; the wheels-off turn phase has
`KF/wheel omega = 0.007`, as expected because the free-spinning wheels are not
body yaw rate.

The DARE is tuned to the quadrature encoder fallback, which is the active wheel
source on the current hardware. The code still accepts the AS5X47 path when it
reports valid motion; re-solve the DARE before relying on it after a repair.

## Multi-Rate Check

The DARE assumes each block is updated at its own rate. The script builds the
100-step error transition with the gyro every 1 ms and the wheel v/omega
updates every 10 ms, then reports the maximum eigenvalue. This is a design
check, not a proof of multi-rate optimality.

## Limitations

- The DARE is stationary; the firmware uses constant gains and does not
  propagate covariance.
- `b_a` and the disturbance terms are tuning values; only the sensor sigmas
  come directly from the logs.
- Heading is integrated externally and has no absolute correction while the
  magnetometer is unavailable.
- Distance and pose error grow from the velocity/yaw-rate errors and are not
  bounded by the DARE.
